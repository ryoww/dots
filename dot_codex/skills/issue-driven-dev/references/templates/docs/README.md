## 一覧と役割

| 文書 | 役割 | 書き換え |
|---|---|---|
| `vision.md` | 誰のためのアプリか、責務、やること、**やらないこと**、判断の基準 | 合意したうえで書き換える。理由は `decisions/` に残す |
| `workflow.md` | Issue から PR までの進め方と、仕様とコードをそろえる決まり | 合意したうえで書き換える |
| `specs/` | 機能ごとの仕様(状態・振る舞い・受け入れ条件)。コードはこの仕様に合わせる | 機能を変える PR で書き換える |
| `decisions/` | 決めたことの背景、決定、ほかの選択肢、根拠、影響 | **追記だけ。消さない・本文を書き換えない** |
| `open-questions.md` | まだ決まっていない項目。`OQ-NNN` | 追記し、解決したら「解決済み」へ移す。消さない |

## 読む順番

1. `vision.md` で、目的と「やらないこと」を確かめる。
2. `workflow.md` で、進め方を確かめる。
3. 作業する機能の仕様を `specs/` で読む。
4. 関係する未解決の項目を `open-questions.md` で、過去の決定を `decisions/` で確かめる。

## 文書どうしの関係

- `vision.md` は、仕様に入れるかどうかを決める基準。「やらないこと」に当たる機能は仕様に入れない。
- 仕様を書いている途中で決められないことが出たら、`open-questions.md` に OQ を起票する。
- OQ が決まったら、`decisions/` に決定を書き、OQ からその決定へリンクする。
- 仕様は決定の**結果**だけを書き、**理由**は `decisions/` へのリンクで示す。

## 一次情報は 1 か所だけ

同じ事実を複数の文書に書かない。ある事実の「正」は 1 文書に置き、他文書は再掲せずリンクする。

| 事実 | 一次情報(正) |
|---|---|
| 何をやり、何をやらないか | `vision.md` |
| 機能の振る舞い・受け入れ条件・実装状況 | `specs/<機能>.md`(一覧は `specs/README.md`) |
| なぜそう決めたか | `decisions/D-XXXX` |
| まだ決まっていないこと | `open-questions.md` |
| 進め方・ブランチ・PR の規約 | `workflow.md` |
| テスト方針・E2E を流す範囲 | `decisions/D-XXXX`(テスト戦略を決めたら番号を入れる) |
| ディレクトリ構成・依存ルール | `decisions/D-XXXX`(構成を決めたら番号を入れる) |
| ライブラリの実物・バージョン | パッケージ定義ファイル(選定理由は `decisions/`) |

## 未確定のことの書き方

記述にステータスの印は付けない。**印が無い記述は、現時点の決定**として読む。

決められないことは本文に「〜は**未確定**(`OQ-NNN`)」と書き、論点そのものは `open-questions.md` に置く。本文とハブが必ず OQ 番号で結ばれるため、どちらか一方に取り残されない。
