テーマ: $ARGUMENTS

決定の記録は**追記のみ**。消さず、本文も書き換えない。覆すときは新しい記録を書く。

## 手順

1. **採番**: `docs/decisions/` の既存ファイルの最大番号 + 1(4 桁ゼロ埋め)。ファイル名は `D-XXXX-英語スラッグ.md`。**同じ番号が既に無いか確認する**(並行する PR で衝突しうる)。衝突したら、後からマージする側が番号を付け直す。
2. **形式**: `docs/decisions/_template.md` を写す。見出しは `# D-XXXX タイトル`。メタ行(日付・決めた人・関係する Issue と PR・解決した未解決の項目・置き換える記録)を埋め、節は 背景・決定・ほかの選択肢・根拠・影響 の順に書く。
3. **内容**:
   - 「ほかの選択肢」が空の記録は作らない。議論が足りなければ、主要な選択肢を調べて比較してから書く。
   - 「根拠」には、参考資料・試した結果・誰の判断かを書く。
   - 「影響」には、書き換えた仕様・コードを書く。
4. **置き換え**: 既存の決定を覆す場合は、新しい記録の「置き換える記録」に旧番号を書く。旧記録のメタ行の直後に、引用ブロックで「**この記録は D-XXXX で置き換えられた。**」と、何が変わったかを足す。旧記録の本文は当時の判断の記録としてそのまま残す。
5. **未解決の項目(OQ)**: 解決した OQ を `docs/open-questions.md` の「解決済み」へ移し、状態を「解決」にして `D-XXXX` へリンクする。残る論点があれば、新しい OQ を起票して記録から参照する。
6. **仕様への反映**: 決定の結果を `docs/specs/` の該当仕様に反映する(理由は書かず `D-XXXX` へリンクする)。決定が `docs/README.md`「一次情報は 1 か所」表や読む順番に関わる場合は、その表も更新する。

すべて日本語・である調。参照は `D-XXXX`・`OQ-NNN`・`specs/<機能>.md` の形で書く。

## してはいけないこと

- ステータス行(承認待ちなど)を持たせる。`docs/decisions/` にある記録は、置き換えの注記が無いかぎり有効な決定として読む。
- 既存の記録を消す、または本文を書き換える。
- 「ほかの選択肢」を空にする。
- 議論が済んでいない論点を決定として書く。決めきれていない論点は OQ に置く。
