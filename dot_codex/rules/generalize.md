# 参考元の汎用化ルール

スキル・テンプレート・雛形・ガイド・ルール文書のように**他のプロジェクトでも使う成果物**を、既存のリポジトリや資料を参考にして作るとき:

- 参考元の固有名を成果物に書かない。対象はプロジェクト名・リポジトリ名・人名・アカウント名・プロダクトの説明・採用している具体的なライブラリや値(桁数・期限など)・Issue や決定の番号。
- 「〜に由来」「〜ではこうしていた」といった由来や経緯の記述を入れない。参考元から得た教訓は、固有名を落として一般的な規則として書く(「一覧表を手で保守すると並行 PR で番号が重複しても気づけない」のように)。
- 例はプレースホルダや抽象的な形で書く。`<owner>/<repo>`、`specs/<機能>.md`、`〈誰〉が〈何をする〉ための〈種類〉アプリ。`、`〈桁数〉桁の数字` のように、読み手が自分の値に置き換えられる形にする。
- 参考元を記録したければ、成果物の外(会話での報告・メモリ・コミットメッセージ)に置く。
- 書き終えたら固有名が残っていないか grep で確かめる。
- 対象外: 参考元のリポジトリ自身に置く文書(そのプロジェクトの ADR・仕様など)や、テスト用の具体的な入力データ。これらは具体名を書いてよい。
